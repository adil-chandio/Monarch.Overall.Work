# Evaluation of eight user-supplied video repositories

## Scope
Question: can these repositories give the agent autonomous YouTube video access and frame-by-frame competitor forensics? Inspected upstream README, repository trees and selected source at the pinned commits below. These are tools, not endorsement of their unverified marketing claims. No competitor video was downloaded and no authentication or bot challenge was bypassed. Two components were smoke-tested locally against our own previously generated 60-second file; this is a tooling test, **not** a new creative deliverable or a target-video analysis.

## Local smoke tests — real execution

**Input:** our existing `deliverables/monarch-pov-fully-rendered-test.mp4`; ffprobe reports 30/1 fps and 1,800 frames over 60 seconds. This prior rejected pilot is used only as an authorized mechanical test input, not as a production reference or validation of quality. Tools and outputs stayed in temporary cache, not the Git repository. No API keys or external video downloads.

1. `claude-real-video` pinned source, CLI, first five seconds, `--no-transcribe --grid`, default settings: extracted 5 sampled frames, deduplicated them to **3**; reported timestamps 0, 1, 2 seconds. Audio was not tested. Default output does not meet the requirement to inspect all frames.
2. Same source's lower-level `extract_frames` function, `fps_floor=1/30`, 0–5 seconds, **without invoking dedup**, output width 540: **150 JPEG frames and 150 reported timestamps**, from 0.0000000 to 4.966667 seconds. This is a concrete all-decoded-frame test on that 30fps fixed-rate interval; JPEG is lossy, and one test does not establish correctness for variable-frame-rate files or arbitrary sources. This function produces visual evidence; an agent must still inspect it. Full coverage requires counting decoded frames and checking PTS, with holds/duplicates retained.
3. `reelbench` `video-shots.mjs seed` on the same full 60-second file: default scene threshold **0.3 reported 0 cuts and 1 shot**; motion track contained 299 samples at 5 Hz. Re-running at threshold **0.1 reported 6 cuts and 6 resulting shots**. Cut counts differ with settings and neither is manually verified ground truth. Automatic outputs must be reviewed and corrected; the motion track is sampled, not every frame.

## Recommendation

Use **claude-real-video's lower-level frame extraction / PTS evidence** for received authorized sources, plus **reelbench's shot and motion tooling** as a candidate timeline that must be visually checked; use **rea-video** as a future exploratory forensic layer after isolated testing. Review the original licenses before vendoring source and do not run third-party installation scripts blindly. For full source-frame coverage, retain duplicates and use source presentation timestamps rather than deduplication or 1-fps samples; inspect both whole-video coverage and dense local intervals.

**Outstanding access blocker:** the user-requested public competitor YouTube videos returned `LOGIN_REQUIRED` from the GitHub runner. These repos do not establish a way around it. Google's official public-URL video-understanding route returned `SERVICE_DISABLED` on the one configured distinct key; it generates sampled model analysis, not original frames. Until an authorized playable input, enabled official service, or rights-cleared source is available and tested, no full competitor-video viewing or frame-by-frame analysis should be claimed.
