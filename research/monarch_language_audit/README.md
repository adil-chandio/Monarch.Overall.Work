# Multilingual YouTube investigation

This folder contains the reproducible, nonrandom evidence behind an editorial language decision. The [Roman Urdu research report](MULTILINGUAL_YOUTUBE_RESEARCH_ROMAN_URDU.md) includes an executive recommendation, sourced multilingual examples, limitations, an original pilot and an approval-first validation plan. It is research, not permission to pivot or publish. The folder does not contain credentials, private analytics, user screenshots, comments, subtitle files, or downloaded videos. The preceding comparison remains in `../monarch_og_audit/`.

The collection plan covers native-script/phrased searches in 17 languages: English, Hindi, Spanish, Portuguese, Urdu, Arabic, Indonesian, French, German, Japanese, Bengali, Turkish, Italian, Chinese, Russian, Korean and Tamil. One common engineering question, two API duration filters and six additional recent-query lanes result in 46 planned searches. The search API's `short` means **under four minutes**, not necessarily a Short; later analysis uses ≤60 seconds as a conservative candidate and ≥4 minutes as a long-form proxy. 61–239 seconds remain explicitly ambiguous. Successful search queries, failed queries, and circuit-skipped queries must all be counted separately; 46 planned does not imply 46 successful.

The channel list is intentionally selected; the plan allowed at most one small-channel, winner-selected result per successful search language. In the recorded run **all 46 searches failed or were circuit-skipped**, so no dynamic winner-selected channels were added. The run resolved **25 of 28 named seeds** and recorded **25 successful bounded inventories, 2,987 video records and 32 channels**. Three queries received nine 429 `rateLimitExceeded` attempts in total; 43 were skipped after the circuit opened. Subsequent source-linked web leads in the report are selected, uneven and not equivalent to successful native API search coverage.

Selected recent upload playlists are bounded to at most four pages; platform-wide distributions and success rates cannot be inferred. Sample medians, highs and lows use at most the newest 30 eligible returned videos **within a channel and duration bucket**, with videos published strictly before `2026-10-23T00:00:00Z`; the trusted session date is November 5 and all retained videos are published before November 6 UTC. The maturity cutoff implies at least 13 days **at the start** of November 5 and at least 14 days **by its end**. Relative to the runner-reported November 13 05:18 snapshot, those same videos are at least 21 days and 5 hours old; this does not backdate their counters to November 5. The mature comparison omits October 23–November 5 publications, and the collector excludes November 6 onward, even though the runner reported November 13. Language codes and native search terms indicate relevance only; actual narration language is not independently established without playback or other reliable corroboration. A regional search does not establish audience country.

**Clock warning:** the actual runner and API server have reported November 13 while the trusted session date is November 5. Public counters and metadata cannot be backdated, even when publication is before November 6; they are runner-reported observations, not verified November 5 numbers. No as-of-now growth, velocity, historical numbers or causation may be inferred from them. Channel subscriber numbers are rounded. A sample cannot prove which channel is actively growing without dated comparable historical receipts.

To re-run locally where an authorized YouTube Data API key is already available:

```sh
python -m unittest discover -s research/monarch_language_audit/tests -v
YOUTUBE_API_KEY="$YOUTUBE_API_KEY" python research/monarch_language_audit/multilingual_youtube.py --output /tmp/language-youtube.json
```

No key should ever be printed or checked in. API errors cause bounded retries and circuit-skipped receipts, not silent success. The original on-branch GitHub Actions workflow reads the existing configured secret and transfers only public metadata as a checksum-verified Git blob; this blob is public and GitHub's retention of it is not guaranteed to be short.

The separate supplemental workflow and its still-review collector were queued but not completed during the report; **their outputs are not used**. Its queued [run](https://github.com/adil-chandio/Monarch.Overall.Work/actions/runs/43372296666) could not be canceled using the current GitHub integration (403), and may use configured API quota if it later starts. The workflow pins its source commit and encrypts the public-still review bundle using `review_public.pem`; the private decryption key is not in the repository. Do not treat the uncompleted collector as verified search or visual evidence.
