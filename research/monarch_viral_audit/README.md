# Monarch YouTube research audit

## Deliverable

[Deep YouTube niche report — Roman Urdu](DEEP_YOUTUBE_NICHE_REPORT_ROMAN_URDU.md) contains the niche assessment, winner/counterexample comparisons, visual evidence, one original 3D pilot script, production blueprint and validation plan. It is a proposal, not a channel pivot or upload approval.

## Time and evidence boundary

The session's trusted date is **2026-11-05**. The research runner **and Google HTTP Date headers** reported **2026-11-12**. Publication is filtered strictly before `2026-11-06T00:00:00Z`, but public counters are from the later runner-reported snapshot and cannot be described as counts as of November 5. Titles, descriptions, thumbnails and extracted text can also change, so their exact November 5 state was not established. This mismatch prevents trustworthy current-growth or velocity claims.

Searches are keyword-selected, non-random and can return irrelevant results; `regionCode=US` means availability, not audience location; `videoDuration=short` means under four minutes, not verified Shorts classification. Public counters, rounded subscriber figures and mixed-age upload samples do not expose private retention, demographics, CTR, RPM, revenue or success probabilities.

13 public `hqdefault` thumbnails were inspected as stills. Competitor videos were not continuously watched or listened to, and thumbnails are not evidence of video timing. Gemini-generated visual descriptions are **unverified sampled model output**, not extracted frames or reliable edit timings. Five unauthenticated caption-only `yt-dlp` requests were blocked by YouTube's bot verification; no attempt was made to bypass it. A separate public page-extraction tool returned transcript-labelled text for 20 of 25 selected IDs, but some sections were sparse or garbled and none was independently verified against audio. Their origin, timing and completeness are unknown. We analyze the returned text, not verified complete competitor scripts, motion curves or soundtrack details.

## Collection architecture

`collect_youtube.py` uses the YouTube Data API v3 via an authorized `YOUTUBE_API_KEY` environment variable and writes the output path passed with `--output`. `forensic_followup.py` uses the existing broad snapshot, public thumbnails/comment metadata, `yt-dlp` for caption-only probes, and an authorized `GEMINI_API_KEY` for official YouTube video-input descriptions. `retry_visual.py` reruns only selected transient model failures and overlap checks. These scripts do not print credentials or download competitor video files. The branch-specific GitHub workflows used repository-held secrets; no key needs to be pasted in chat.

Reruns may use quota, model availability or changed public content and are not guaranteed to reproduce counters or descriptions. The model version and sampling windows are recorded alongside each response.
